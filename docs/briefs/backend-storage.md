# Backend wave 2a — buckets, objects, quotas, inventory

Read: docs/BUILD-RULES.md, docs/ARCHITECTURE.md, docs/API.md (incl. Additions), docs/FEATURE-CHECKLIST.md, apps/api/README.md (foundation guide). Build on the existing foundation; do not restructure it.

Scope (`apps/api/src/modules/{buckets,objects,quotas,inventory}`):
- Inventory refresher: caches bucket lists + stats per server (native usage drivers: MinIO data-usage via admin API, Ceph bucket stats, Garage bucket info; otherwise throttled ListObjectsV2 scan with a per-server budget), daily size snapshots per bucket for quota trends and dashboard growth. Offline servers keep cached rows with `unavailable: true`. Emits `inventory.updated`.
- Buckets: every endpoint under "Buckets" in docs/API.md + `POST /buckets/bulk` + `…/notifications/status`. Access presets generate the canonical public-read policy. Versioning, object lock (only at creation; report NOT_SUPPORTED otherwise), lifecycle (map contract ⇄ S3 XML shapes both ways), CORS, tags, replication, notifications, quota (native via driver where supported — MinIO admin set-bucket-quota, Ceph admin, Garage admin; else app-level alert quota), delete (409 BUCKET_NOT_EMPTY unless force which empties via job — coordinate: create job rows in the jobs table using the shared JobsService interface if it exists; if the jobs module is not there yet, implement a minimal `JobsService.enqueue()` contract in `src/modules/jobs/jobs.port.ts` and let wave 2c implement the engine).
- Objects: every endpoint under "Objects" + import-url + storage-class. Streaming everywhere (no buffering of bodies): upload with `@aws-sdk/lib-storage` Upload using settings part size/concurrency, download with Range passthrough and correct headers, ZIP via `archiver` streaming, copy across servers (server-side CopyObject when same server, stream otherwise, multipart copy for > 5 GB), rename = copy+delete preserving metadata/tags, delete with versions (DeleteObjects batches of 1000), presign with expiry limits, restore-version via copy of versionId, metadata update via copy-in-place REPLACE, retention/legal hold, tags. Record activity for every mutation (upload/download included, with bytes).
- Quotas: `/quotas` aggregation + quota watcher (threshold crossing → notification + activity, once per crossing).
- Tests: unit tests for mappers (lifecycle/CORS/policy presets), e2e tests against MinIO and SeaweedFS containers (S3_IT=1) covering create bucket with versioning/lock/quota, upload (small + multipart), list with prefixes/cursor, download with range, zip, copy/move across the two servers, rename, versions/restore, presign GET works via fetch, delete with versions, lifecycle/CORS/policy round trips, quota enforcement on MinIO.

Report: short; what you ran and results; any contract changes.

Also: `GET /buckets/export.csv` and `GET /quotas/export.csv` (see API.md). Note: an API instance may already be running on :3000 (admin/dev-password-123, apps/api/.env) with MinIO + SeaweedFS containers up; restart it after rebuilding when you need your changes live. Another backend agent (IAM) works in parallel under src/providers/iam and src/modules/{iam-*,access-keys}; keep app.module/registry edits small and additive.
